# brownie

**不在の間に、溜めた作業を1件ずつ使い捨ての Claude Code セッションで進める無人実行の司令塔。**
司令塔は Python（`runner.py`）で、LLM ではない。待ちと取りまとめにトークンを使わない。

名前は、家の人が寝ている間に仕事を片付ける妖精（ブラウニー）から。

> 個人の作業場で実際に動かしながら作ったものを、そのまま公開している。
> 他の環境へ持っていくには、下の「同梱していないもの」が要る。

---

## なぜ作ったか

長い会話セッションに夜通し作業させると、往復のたびに膨らんだ文脈を丸ごと読み直す。
在席していれば途中の判断に価値があるが、不在の間は判断が入らないので、その文脈に払う理由がほぼ無い。

そこで次の形にした。

- 司令塔は Python。作業票を1枚ずつ、新しい `claude -p` セッションに渡す。
- 各セッションは文脈が既定 15 万トークンに達したら、進捗をファイルに書いて終わる。続きは新しいセッションが読む。
- 作業票が尽きたら、元の文書が変わるまでトークン 0 で待つ。

## 一晩の流れ

```
始める.bat → 進めるプロジェクトを番号で選ぶ（0件なら始めない）
  │
  ├ 起動前の確認   自己試験／フックの設定／合流の入口が使えるか。だめなら始めない
  ├ 仕分け         各プロジェクトの PENDING.md・HANDOFF.md・inbox.md から作業票を作る
  ├ 作業           票ごとに git の作業コピー（worktree）とブランチを作り、1票＝1セッションで進める
  ├ 関門と合流     評価役が差分を既存の決裁と照合 → 試験 → 本流へ合流
  ├ 審判官         作業役とは別のセッションが、基準5項目で実物を採点（作業と並行）
  ├ 待機           票が尽きたらトークン0で待つ。元の文書が変わったら仕分けし直す
  └ 報告           票は「できた／保留／失敗」のちょうど1つで終わる。朝に読む1枚と全文版を書く
```

止まる条件は、STOP ファイル（`ブラウニーを止める.bat`）・1回の起動の上限額・利用上限・空き容量の不足・例外の連続。
既定では時間では終わらない（`NIGHT_MAX_HOURS` / `NIGHT_END_AT` で指定できる）。

## 部品

| ファイル | 役割 | トークン |
|---|---|---|
| `runner.py` | 司令塔。仕分け → 作業 → 関門 → 合流 → 報告を回す | 使わない |
| `choose_projects.py` | 起動時の選択画面。選んだ結果を `projects.txt` に書く | 使わない |
| `finish_gate.py` | 合流の直前に走る関門（評価役と試験）。結果に夜ごとの鍵で署名する | 評価役の分だけ |
| `usage_window.py` | 利用枠（5時間枠・7日枠）の使用率を `claude -p` の出力から読んで判定する。読み取りと判定だけで、待つ・知らせるのは `runner.py` | 使わない |
| `hooks/night_guard.py` | 無人のセッションにだけ差し込むフック。取り消せない操作を拒む | 使わない |
| `prompts/triage.md` | 仕分け役の指示 | 使う |
| `prompts/work.md` | 作業役の指示（進捗の書き方・終わり方） | 使う |
| `prompts/review.md` | 評価役の指示（読むだけ） | 使う |
| `prompts/resolve.md` | 合流で衝突したときだけ起こす解消役の指示 | 使う |
| `prompts/judge.md` `judge/criteria.md` | 審判官の指示と採点基準。**基準は作業役に見せない** | 使う |
| `tests/` | 下の「試験」 | 偽の claude を使うものは 0 |

## 守り — 越えない線

無人のセッションは権限の確認を省いて動かす（`bypassPermissions`）。歯止めは `hooks/night_guard.py` の PreToolUse フックだけ。

常に止めるもの（`NIGHT_GUARD` の設定に関係なく効く）:

- `git push` とリモートの操作、外部への発信
- Claude の設定・フック・エージェント定義、git の全体フックへの書き込み
- 入れ子の `claude`（入れ子にはフックが付かない）
- 作業コピーの外への書き込みと削除
- 登録したゲームサーバーの場所に触れるコマンド

**限界も書いておく。** 正規表現の拒否リストは「うっかり」は防げても、意図した迂回は防げない。
スクリプトの中からの操作、変数に入れたコマンドなど、通り抜ける筋が残っていることは把握している。
だから線を越えたかどうかは、フックだけでなく司令塔側でも確かめる
（作業の前後で作業コピーの外の状態を比べ、変わっていれば合流させずに保留にする）。

## 試験（トークン 0）

配管の確認に本物のモデルを使うと、試験のたびに費用と待ち時間がかかる。
そこで偽の `claude`（`tests/fake_claude.py`）と、合流の入口のスタブ（`tests/wt_stub.py`）を用意した。

```bash
python make_settings.py              # 最初に1回（下の「使い方」）
python tests/selftest.py             # 砂場で仕分け→作業→合流→報告まで通す
python tests/test_guard.py           # 守り（拒否リスト）
python tests/test_lineguard.py       # 守り（越えない線）
python tests/test_guard_holes.py     # 守り（敵対レビューで見つかった穴の回帰）
python tests/test_leads.py           # 仕分けへ渡す手がかりの拾い方
python tests/test_precheck.py        # 着手前の検査（本体の未コミットと重なる票を始めない）
python tests/test_reflow.py          # 前の夜の合流待ちを、次の起動のはじめに流し直す
python tests/test_usage_window.py    # 利用枠の見張り（しきい値で待って再開する）。1〜2分かかる
python tests/test_records_later.py   # 記録だけ後から合流。実物の wt.py が要る（下の注）
```

`tests/test_records_later.py` だけは、合流の入口の実物（`wt.py`）を使う。`wt.py` は同梱していないので、
この公開版だけで回すと途中で止まる（終了コード 1）。手元に `wt.py` があるときは、`--wt <場所>` か
環境変数 `NIGHT_SANDBOX_WT_PY` で指す。ほかの試験はスタブ（`tests/wt_stub.py`）で動く。

`tests/sabotage_overnight.py` は、司令塔をわざと壊した版で試験が落ちることを確かめる（試験が嘘の合格を出さないかの確認）。

## 使い方

前提: Windows・Python 3.12・git・Claude Code CLI（`claude`）。

1. このフォルダを、作業場（各プロジェクトのフォルダが並ぶ場所）の直下に **`BrownieProject` という名前で**置く。
   司令塔は「このフォルダの1つ上」を作業場として読む（`NIGHT_EVAR_ROOT` で変えられる）。
   自分自身を書き換えさせない守りと、試験用のひな形を本物と取り違えない除外は、このフォルダ名で当てている。
   別の名前で置くと、どちらも当たらない。
2. 各プロジェクトに `PENDING.md`（これからやること）・`HANDOFF.md`（今の状態）・`DECISIONS.md`（判断の記録）を置く。
   仕分け役はここから作業票を作る。
3. フックの設定を作る。

   ```bash
   python make_settings.py
   ```

4. `ブラウニーを始める.bat` をダブルクリックし、進めるプロジェクトを番号で選ぶ。
5. 止めるときは `ブラウニーを止める.bat`。走っているセッションが終わってから止まる。
6. 朝は `reports/<日付>.md` を読む。

設定は環境変数で変える。一覧は [.env.example](.env.example)（説明用。プログラムは OS の環境変数を読む）。

## 同梱していないもの

この公開版だけでは本番の運用はできない。次のものを作者の環境から持ってきていないため。

| 無いもの | 何に使うか | 無いとどうなるか |
|---|---|---|
| `wt.py`（git 統合の入口。`start` / `finish --gate`） | 作業コピーを作り、関門を通して本流へ合流する | 司令塔は起動前の確認で止まる（`NIGHT_WT_PY` で場所を指す）。試験はスタブで動く（`tests/test_records_later.py` だけは実物が要る） |
| `merge_md.py`（統治文書の見出し単位のマージドライバ） | 複数の作業が同じ判断ログに追記したときの衝突を減らす | 無くても動く。衝突は解消役に回る |
| `install_md_merge.py`（上のマージドライバを各リポジトリへ登録する） | 砂場の試験で、本番と同じ衝突の形を作る | 無くても動く（登録を飛ばす） |
| `ctx_now.py`（会話記録から今の文脈の大きさを読む） | フックが「文脈が上限に達したので、進捗を書いて終われ」と返すのに使う | **区切りが黙って働かない**（フックは読めなければ何もせずに通す）。1票の合計時間と上限額の歯止めは残る |
| `toast.py`（Windows の通知） | 始められなかったときの通知 | 無くても動く（通知が出ないだけ） |

**作者の作業場に合わせて書いてある部分**が2つある。別の作業場で使うなら、ここを書き換える。

- 守る場所の表（`hooks/night_guard.py` の `FROZEN` と `FIXED_SERVER_PATHS`、サーバーの登録簿の場所 `NIGHT_SERVERS_JSON`）。
  公開版ではフォルダ名を作り物（`GameAProject`・`GameBProject`・`KeeperProject` など）に置き換えてある。
  試験も同じ名前を使うので、そのままでも試験は通る。
- 作業の指示（`prompts/`）。文書の時制の分け方や決裁の書き方など、作者の作業場の決まりを前提にしている。
  指示の中の `C:\Workspace\...` は作業場の場所の例で、その場所に文書があるわけではない。

コードのコメントにある `[E-045]` のような番号は、非公開の判断ログの番号。
